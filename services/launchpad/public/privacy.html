PRIVACY & SECURITY

Your instance, your choices.

This page describes the technical boundaries of the workspace. It is not a compliance certificate or legal advice.

DATA FLOW

Where information goes

  • 01Workspace filesFiles and terminal commands are stored on this instance's IDE volume. Coding agents can read and change files available to the IDE user.
  • 02Git repositoriesForgejo stores repositories on its persistent volume and uses the private PostgreSQL service. Public registration is disabled and sign-in is required to browse.
  • 03Provider credentialsOmniRoute stores provider configuration in its persistent database. The IDE receives only an inference key configured by the operator.
  • 04Prompts and code contextAgent requests pass from the IDE to OmniRoute and then to the selected provider. Provider processing may occur outside Railway EU West. Review that provider's terms and data controls.
  • 05Network accessPrivate networking limits inbound service access. It does not restrict outbound connections. Repository code and agent commands can make outbound requests from the IDE.

OPERATOR CHECKS

Before using this instance

  • AUse separate credentialsKeep IDE, Forgejo, and OmniRoute passwords distinct. The launchpad uses the shared workspace sign-in. Do not give coding agents administrative service credentials.
  • BProtect scoped keysA coding agent must be able to use its inference key. Code running as the IDE user may also read it, so revoke and replace it if that user context is compromised.
  • CBack up and restoreBackups are the operator's responsibility. A backup is not verified until a restore has been run and the restored data checked.
  • DCheck legal dutiesRegion selection and technical controls do not establish GDPR compliance. Review subprocessors, DPAs, retention, access requests, and provider transfer terms for your use case.
